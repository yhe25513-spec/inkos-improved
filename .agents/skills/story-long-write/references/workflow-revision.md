# workflow-revision.md：大修工作流

本文件为"大修/回炉"场景的完整指引。SKILL.md 路由到本文件后，按以下流程执行。

---

## 适用条件

- 用户说"修改第X章""回炉第X章""重写第X章"
- 目标：修改已写好的章节内容

> 用户必须指定章节号或章节名。无法自动推断需要修改哪一章。

---

## Step 0：项目结构检测（必须先执行）

**⚠️ 项目可能使用不同的目录结构，开始修改前必须检测。**

1. 检测项目的实际目录结构：
   - 检查 `chapters/` 目录是否存在 → 项目使用 **webnovel-writer 格式**（`chapters/000X_章名.md`）
   - 检查 `正文/` 目录是否存在 → 项目使用 **story-long-write 格式**（`正文/第00X章_章名.md`）
   - 如果项目根下不存在上述目录，检查 `books/*/` 子目录中的项目，用 `ls books/*/chapters/ 2>/dev/null` 和 `ls books/*/正文/ 2>/dev/null` 确认
2. 记录检测结果，后续所有文件操作必须使用实际检测到的路径格式：
   ```
   项目结构摘要：
   - 项目根目录：{实际的book目录}
   - 章节目录：chapters/ 或 正文/
   - 章节命名格式：000X_章名.md 或 第00X章_章名.md
   - 是否存在索引文件：chapters/index.json (yes/no)
   - 跟踪/大纲/设定目录：story/ 或 大纲/+设定/+追踪/
   ```

## Step 1：定位章节

1. 根据"第X章"找到文件（按优先级尝试）：
   - 如果 Step 0 检测到 `chapters/`，用 `ls chapters/` 列出文件，按编号匹配第 X 章
   - 如果 Step 0 检测到 `正文/`，用 `ls 正文/` 按 `第X章_*.md` 匹配
   - 两个目录都不存在时，用 `find . -name "*第X章*" -o -name "*00{X-1}*"` 全局搜索
2. **定位成功后，将该文件的完整路径记录为 `$CHAPTER_FILE`，后续所有读写操作都使用这个实际路径。**
3. 如果用户说的是章节名而非编号，搜索 `*{关键词}*` 或 `*{关键词}_*.md`
4. 找不到时让用户确认具体章节
5. 如果用户指定段落范围（"第3-5段"/"那场打斗"/"对话部分"），记录为局部修改目标

---

## Step 2：加载上下文

加载比日常写作更多的上下文（因为修改需要理解前后衔接）：

| 序号 | 文件 | 用途 | 如果不存在 |
|------|------|------|-----------|
| 1 | `正文/第{X}章_*.md` | 待修改章节 | 必须存在 |
| 2 | `大纲/细纲_第{X}章.md` | 原始写作计划 | 跳过 |
| 3 | `正文/第{X-1}章_*.md` | 前一章（衔接） | 第1章时加载 `设定/世界观/背景设定.md` 替代 |
| 4 | `正文/第{X+1}章_*.md` | 后一章（衔接） | 末章时检查 `大纲/细纲_第{X+1}章.md`（如有）确保连续性 |
| 5 | `追踪/伏笔.md` | 涉及的伏笔 | 跳过 |
| 6 | `设定/角色/{相关角色}.md` | 本章涉及角色 | 跳过 |

**相关角色判定**：从 `大纲/细纲_第{X}章.md` 中提取角色名。如果细纲不存在，从待修改章节正文中搜索 `设定/角色/` 目录下的角色名关键词。将角色名映射为文件名：`设定/角色/{角色名}.md`。

---

## Step 3：修改

1. **阅读原文**：读取 `$CHAPTER_FILE`（Step 1 定位到的实际文件路径），记录原始字数
2. **备份原文**：将原文复制为 `$CHAPTER_FILE` 所在目录下的 `$CHAPTER_BASENAME_原稿_{YYYYMMDD}.md`（如 `chapters/0002_龟兔与废铁_原稿_20260627.md`），确保可回退
3. **确认修改范围**：问用户是"全文重写"还是"修改特定段落"
   - 全文重写：基于细纲重新写，保留备份
   - 局部修改：只改指定段落（按场景序号或关键词定位），保持其他部分不变
4. **执行修改**：使用 Write/Edit 工具**直接改写 `$CHAPTER_FILE` 文件**。不要创建新文件，不要改变文件路径。
   - 如果 spawn narrative-writer agent：必须在 prompt 中传入 `$CHAPTER_FILE` 的完整路径，要求 agent 用 Write/Edit 写到同一个文件
   - 确保修改后的文件大小 > 100 bytes，不为空
5. **字数对比**：修改后与原文字数差异 > 30% 或 > 800 字时提醒用户（取较大值）
6. **更新章节索引**：如果项目有 `chapters/index.json`，更新对应章节的以下字段：
   - `wordCount`：修改后的实际字数
   - `updatedAt`：当前时间（ISO 8601）
   - `status`：如原状态为 `ready-for-review`，改为 `revised`（标记等待审查）
   - `lengthTelemetry.finalCount`：修改后字数

**资料研究（按需）**：如果修改涉及需要验证的外部事实（历史年代、地理方位、职业细节等），spawn `story-researcher` agent 搜索验证。

---

## Step 4：级联检查

修改完成后，逐一检查是否影响后续章节：

1. **伏笔检查**：对比修改前后的伏笔列表（读取旧快照 vs 新内容），标记变化项：
   - 新增伏笔 → 添加到伏笔跟踪文件（优先 `story/pending_hooks.md`，其次 `追踪/伏笔.md`）
   - 删除伏笔 → 从伏笔跟踪文件移除，并检查后续章节是否引用该伏笔
   - 修改伏笔 → 更新描述，检查后续引用是否一致
2. **时间线检查**：对比修改前后的事件顺序，更新项目的时间线文件（优先 `story/current_state.md`，其次 `追踪/时间线.md`）
3. **后续影响**：如果修改改变了角色状态/关系/世界观设定，扫描后续章节正文标记受影响项：

```
⚠️ 修改第{X}章后，以下章节可能需要同步调整：
- 第{X+1}章：{原因}（建议检查）
- 第{X+3}章：{原因}（建议检查）
```

4. **正文元信息扫描**：检查标题行以外是否混入 `第[一二三四五六七八九十百千万两0-9]+章|上一章|上章|前一章|本章|这一章|前文|后文|伏笔|细纲|读者` 这类写作工程词，命中即改成角色当下可感知的事件锚点或相对时间；故事内真实阅读/讨论”第X章”或真实读者身份语境除外
5. **禁用词扫描**：对照 `references/banned-words.md` 检查修改后的内容
6. **验证文件确实被修改**：用 `ls -la $CHAPTER_FILE` 确认文件大小和修改时间已更新；读取文件前 3 行确认修改生效。如果文件未变化，重新执行 Step 3 写入。

---

## Step 5：质量检查

对修改后的章节执行 Phase 5 质量检查（至少包含）：

1. **禁用词扫描**：如 Step 4 未覆盖全章，再次扫描
2. **正文元信息扫描**：标题行以外不得出现 `第[一二三四五六七八九十百千万两0-9]+章|上一章|上章|前一章|本章|这一章|前文|后文|伏笔|细纲|读者` 这类写作工程词；故事内真实阅读/讨论”第X章”或真实读者身份语境除外
3. **人物一致性**：修改后的角色行为是否与角色设定一致
4. **节奏检查**：修改是否破坏了章节节奏
5. **Pipeline 同步**：修改完成后，运行 `sub_agent(agent="auditor")` 对修改后的章节执行审查，确保章节状态被正确记录到 index.json 和快照体系中。如果章节文件通过 Write/Edit 直接修改（未经过 sub_agent writer/reviser），这一步尤其重要。
5. **脚本复扫**：对修改后的章节文件运行质量脚本（使用 Step 1 定位到的实际文件路径 `$CHAPTER_FILE`）：
   - `node .agents/skills/story-long-write/scripts/normalize-punctuation.js $CHAPTER_FILE`
   - `node .agents/skills/story-long-write/scripts/check-ai-patterns.js --check $CHAPTER_FILE`
6. **章节索引二次验证**：如果项目使用 `chapters/index.json`，确认 Step 3 的更新已生效

> 完整 Phase 5 检查清单见 SKILL.md Phase 5。

## 常见问题

| 问题 | 处理 |
|------|------|
| 用户没说改哪里 | 问"你想改哪一章？哪方面？情节/节奏/对话/描写？" |
| 修改后字数暴增/暴减 | 提醒用户，由用户决定是否调整 |
| 连续改多章 | 逐章修改，每章独立执行 Step 2-5 |
| 改完发现后续不一致 | 列出受影响章节，由用户决定是否现在修改 |
| 找不到章节文件 | Step 0 检测项目结构 + Step 1 按格式查找。确认文件路径后再操作 |
| 修改完但文件没变化 | 检查是否写到了错误路径（正文/ vs chapters/）；Step 4.6 验证文件修改时间 |
| 章节界面看不到修改 | 检查 index.json 是否已更新（Step 3.6）；确认修改写到了 chapters/ 而非 正文/ |
