## 1. 环境准备与安装

### 1.1 系统要求

| 项目 | 要求 |
|------|------|
| Node.js | >= 20（推荐 22+，启用 SQLite 记忆库） |
| pnpm | >= 9 |
| 操作系统 | Windows / macOS / Linux |

### 1.2 安装

**方式一：全局安装（推荐普通用户）**

```bash
npm install -g @actalk/inkos
```

安装后你将获得 `inkos` 命令。

**方式二：从源码构建（推荐开发者）**

```bash
git clone <仓库地址> inkos-dev
cd inkos-dev
pnpm install
pnpm build
# 使用 node packages/cli/dist/index.js 或 link 到全局
pnpm --filter @actalk/inkos link --global
```

### 1.3 验证安装

```bash
inkos --version
inkos doctor
```

`inkos doctor` 会诊断你的环境、Node 版本、LLM 配置状态。

## 2. 初始化项目

### 2.1 创建项目

```bash
# 在当前目录初始化
inkos init

# 创建到子目录
inkos init my-novel

# 指定默认语言
inkos init my-novel --lang zh
```

### 2.2 项目结构

初始化后的目录结构：

```
my-novel/
├── inkos.json          # 项目配置（核心）
├── .env                # 项目级环境变量（可选）
├── .gitignore
├── .nvmrc              # Node 版本（22）
├── books/              # 所有书籍的父目录
├── radar/              # 市场雷达扫描结果
└── .inkos/             # 项目级运行时数据
    ├── secrets.json    # API Key 存储
    ├── skills/         # 自定义技能
    └── sessions/       # 交互会话记录
```

### 2.3 inkos.json 配置文件

`inkos.json` 是项目的核心配置文件，初始化时生成：

```json
{
  "name": "my-novel",
  "version": "0.1.0",
  "language": "zh",
  "llm": {
    "provider": "openai",
    "service": "custom",
    "configSource": "studio",
    "baseUrl": "",
    "model": "",
    "apiFormat": "chat",
    "stream": true
  },
  "notify": [],
  "inputGovernanceMode": "v2",
  "daemon": {
    "schedule": {
      "radarCron": "0 */6 * * *",
      "writeCron": "*/15 * * * *"
    },
    "maxConcurrentBooks": 3
  }
}
```

**关键字段说明**：

| 字段 | 说明 |
|------|------|
| `language` | 默认写作语言（`zh` 中文 / `en` 英文） |
| `llm.provider` | LLM 提供商类型（`openai` / `anthropic` / `custom`） |
| `llm.service` | 服务名（如 `deepseek`、`moonshot`、`minimax`） |
| `llm.configSource` | 配置来源（`env` 从环境变量 / `studio` 从 Studio 界面） |
| `inputGovernanceMode` | 输入治理模式（`v2` 推荐 / `legacy` 兼容旧版） |
| `daemon` | 守护进程配置（自动写作） |

## 3. 配置 LLM 服务

InkOS 内置 40+ 个 LLM 服务提供商。你需要至少配置一个才能开始写作。

### 3.1 快速配置（推荐）

**方式一：全局配置命令**

```bash
# 以 DeepSeek 为例
inkos config set-global \
  --provider openai \
  --api-key sk-your-key-here \
  --model deepseek-chat \
  --base-url https://api.deepseek.com/v1

# 以 Moonshot (Kimi) 为例
inkos config set-global \
  --provider openai \
  --api-key sk-your-key-here \
  --model moonshot-v1-auto \
  --base-url https://api.moonshot.cn/v1

# 以 Anthropic (Claude) 为例
inkos config set-global \
  --provider anthropic \
  --api-key sk-ant-your-key-here \
  --model claude-sonnet-4-20250514 \
  --base-url https://api.anthropic.com
```

配置写入 `~/.inkos/.env`，所有项目共享。

**方式二：启动 Studio 在界面配置**

```bash
inkos studio
```

在浏览器中打开 Studio → 服务管理 → 添加服务 → 填入 API Key。

**方式三：编辑 .env 文件**

在项目根目录创建 `.env`：

```bash
INKOS_LLM_PROVIDER=openai
INKOS_LLM_BASE_URL=https://api.deepseek.com/v1
INKOS_LLM_API_KEY=sk-your-key-here
INKOS_LLM_MODEL=deepseek-chat
INKOS_LLM_SERVICE=deepseek
INKOS_LLM_TEMPERATURE=0.7
INKOS_DEFAULT_LANGUAGE=zh
```

### 3.2 配置优先级

配置按以下优先级从低到高合成（高优先级覆盖低优先级）：

```
Studio/项目配置 (inkos.json)
  → .inkos/secrets.json（API Key）
  → 全局 ~/.inkos/.env
  → 项目 .env
  → 当前进程环境变量
  → CLI 参数（--service / --model 等）
```

### 3.3 多模型路由

你可以为不同的 Agent 配置不同的模型：

```bash
# 写手用 Claude（创意写作强）
inkos config set-model writer claude-sonnet-4-20250514 \
  --provider anthropic \
  --base-url https://api.anthropic.com \
  --api-key-env ANTHROPIC_API_KEY

# 审计用 GPT-4o（逻辑检查强）
inkos config set-model auditor gpt-4o \
  --provider openai \
  --api-key-env OPENAI_API_KEY

# 查看路由配置
inkos config show-models
```

**支持的 Agent 名称**：`writer`（写手）、`auditor`（审计）、`reviser`（修订）、`architect`（建筑师）、`radar`（雷达）、`chapter-analyzer`（章节分析）

### 3.4 验证配置

```bash
inkos doctor
```

输出会显示：当前配置模式、服务名、模型名、API Key 来源、API 连通性测试结果。

### 3.5 支持的常用服务商

| 服务名 | baseUrl | 推荐模型 |
|--------|---------|---------|
| `deepseek` | https://api.deepseek.com/v1 | deepseek-chat |
| `moonshot` | https://api.moonshot.cn/v1 | moonshot-v1-auto |
| `minimax` | https://api.minimaxi.com/v1 | MiniMax-M2.7 |
| `zhipu` | https://open.bigmodel.cn/api/paas/v4 | glm-4-plus |
| `anthropic` | https://api.anthropic.com | claude-sonnet-4-20250514 |
| `openai` | https://api.openai.com/v1 | gpt-4o |
| `google` | - | gemini-2.5-flash |
| `ollama` | http://localhost:11434/v1 | （本地模型） |

完整列表运行 `inkos config list-models <service>` 查看。

## 4. 创建新书

### 4.1 基本创建

```bash
inkos book create \
  --title "吞天魔帝" \
  --genre xuanhuan \
  --platform tomato \
  --chapter-words 3000 \
  --target-chapters 200
```

**参数说明**：

| 参数 | 必填 | 说明 |
|------|------|------|
| `--title` | 是 | 书名 |
| `--genre` | 是 | 题材 ID（见第 15 节） |
| `--platform` | 是 | 目标平台：`tomato`（番茄）/ `feilu`（飞卢）/ `qidian`（起点）/ `other` |
| `--chapter-words` | 否 | 每章字数（默认 3000，最小 1000） |
| `--target-chapters` | 否 | 目标章数（默认 200） |
| `--brief` | 否 | 创作简报文件路径 |
| `--lang` | 否 | 写作语言（默认继承项目配置） |
| `--json` | 否 | 输出 JSON 格式 |

### 4.2 带创作简报创建

准备一个 Markdown 文件 `my-ideas.md`：

```markdown
# 吞天魔帝

## 核心设定
少年林轩被家族抛弃后，意外获得上古魔帝传承，踏上修仙之路。

## 主角
- 林轩：16 岁，性格隐忍果断，被家族视为废物
- 苏婉儿：女主，天才少女，表面冷漠内心温柔

## 核心冲突
- 家族恩怨：林轩被逐出家族，誓要复仇
- 魔帝传承：力量强大但伴随代价
- 正邪对立：修仙界正派对魔道的追杀

## 目标
200 章长篇，前期打脸爽文，中后期格局展开。
```

然后创建：

```bash
inkos book create --title "吞天魔帝" --genre xuanhuan --platform tomato --brief my-ideas.md
```

### 4.3 创建后发生了什么

`inkos book create` 会调用 Architect Agent 生成基础设定：

1. **故事框架**（`story/outline/story_frame.md`）：主题、核心冲突、世界铁律、终局
2. **卷纲**（`story/outline/volume_map.md`）：分卷规划与节奏
3. **角色卡**（`story/roles/`）：每个角色一个 Markdown 文件
4. **规则卡**（`story/book_rules.md`）：创作规则与禁忌
5. **伏笔池**（`story/pending_hooks.md`）：初始伏笔
6. **作者意图**（`story/author_intent.md`）：长期创作方向
7. **初始快照**（`story/snapshots/0/`）：建书时的状态备份

### 4.4 书籍目录结构

```
books/tuntian-modi/
├── book.json                    # 书籍配置
├── chapters/                    # 章节正文
│   ├── index.json               # 章节索引
│   ├── 0001_第一章_觉醒.md
│   └── 0002_第二章_传承.md
├── story/                       # 故事资产
│   ├── author_intent.md         # 作者意图
│   ├── current_focus.md         # 当前聚焦
│   ├── book_rules.md            # 规则卡
│   ├── current_state.md         # 当前状态（每章更新）
│   ├── pending_hooks.md         # 伏笔池
│   ├── chapter_summaries.md     # 章节摘要
│   ├── emotional_arcs.md        # 情感弧线
│   ├── outline/                 # 大纲
│   │   ├── story_frame.md
│   │   └── volume_map.md
│   ├── roles/                   # 角色卡
│   │   ├── 主要角色/
│   │   └── 次要角色/
│   ├── runtime/                 # 运行时产物
│   ├── state/                   # 结构化状态（JSON）
│   ├── snapshots/               # 状态快照
│   └── memory.db                # SQLite 记忆库（Node 22+）
└── .inkos/                      # 书级运行时数据
    ├── humanity_profile.json    # 真人感画像
    └── learning/                # 用户偏好
        ├── edit_log.json
        └── preferences.json
```

```bash

# 查看当前书状态

# 查看详细章节状态
inkos status --chapters
```

## 5. 写作章节

### 5.1 写下一章（核心命令）

```bash
# 写下一章（完整管线：规划→编排→写作→审计→修订→后处理）
inkos write next

# 连写 5 章
inkos write next --count 5

# 指定字数
inkos write next --words 2500

# 传入创作指导
inkos write next --context "本章重点写师徒矛盾，主角发现师父的秘密"

# 从文件传入指导
inkos write next --context-file ./chapter-notes.md

# 静默模式（减少输出）
inkos write next -q
```

### 5.2 写作管线详解

`inkos write next` 执行以下步骤：

```
1. 获取写入锁（防止并发冲突）
2. 加载书籍配置和状态
3. 规划章节意图（Planner Agent）
4. 编排上下文（Composer Agent）
5. 角色圆桌讨论（CharacterRoundtable）
6. 撰写正文（Writer Agent）
7. 连续性审计（ContinuityAuditor，37 维度）
8. AI 痕迹检测（analyzeAITells）
9. 敏感词检测
10. 伏笔回收验证
11. 信息边界检查
12. 修订（Reviser Agent，如有问题）
13. 后处理（反 AI + 真人感 + 情感注入）
14. 落盘（章节文件 + 状态更新 + 快照）
15. 释放锁
```

### 5.3 只写草稿（不审计）

如果你想要快速产出内容，后续再统一审计：

```bash
inkos draft --words 3000 --context "主角逃脱追杀"
```

草稿状态为 `drafted`，不会触发审计和修订。

### 5.4 批量连写

```bash
# 连写 10 章，每章间隔 5 秒
inkos batch-write --count 10 --delay 5000

# 失败时停止
inkos batch-write --count 20 --stop-on-failure

# 带创作指导
inkos batch-write --count 5 --context "进入第一卷高潮"
```

### 5.5 重写章节

如果你对某章不满意，可以重写（会恢复到该章前的状态快照，删除该章及后续章节）：

```bash
# 重写第 5 章
inkos write rewrite 5

# 强制重写（跳过确认）
inkos write rewrite 5 --force

# 带新指导
inkos write rewrite 5 --brief "加强情感冲突"
```

### 5.6 单步操作

如果你只想执行管线的某一步：

```bash
# 只规划下一章意图
inkos plan chapter --context "本章写主角突破"

# 只编排运行时上下文
inkos compose chapter
```

## 6. 审计与修订

### 6.1 审计章节

审计会从 37 个维度检查章节质量：

```bash
# 审计第 10 章
inkos audit 10

# 审计指定书的指定章节
inkos audit my-book 10

# 输出 JSON 格式
inkos audit 10 --json
```

**审计维度包括**：剧情连贯性、角色一致性、时间线、伏笔回收、世界观设定、文风一致性、字数合规等。

### 6.2 修订章节

修订支持 5 种模式：

```bash
# 轻微润色（修复小问题）
inkos revise 10 --mode polish

# 定点修复（只修审计发现的问题）
inkos revise 10 --mode spot-fix

# 大幅重写（保留核心剧情，重写表达）
inkos revise 10 --mode rewrite

# 结构重组（改变叙事结构）
inkos revise 10 --mode rework

# 反 AI 检测改写（专门降低 AI 痕迹）
inkos revise 10 --mode anti-detect
```

### 6.3 修复状态降级

如果某章因异常导致状态不一致（`state-degraded`）：

```bash
# 修复状态（不重写正文）
inkos write repair-state 10

# 从已编辑的章节正文重建 truth 文件
inkos write sync 10
```

## 7. 审阅与导出

### 7.1 审阅流程

写作完成的章节状态为 `ready-for-review`，需要你审阅：

```bash
# 列出待审阅章节
inkos review list

# 通过第 5 章
inkos review approve 5

# 批量通过所有待审章节
inkos review approve-all

# 拒绝第 5 章（默认回滚状态）
inkos review reject 5 --reason "剧情不合理"

# 拒绝但保留后续章节
inkos review reject 5 --reason "需要修改" --keep-subsequent
```

### 7.2 导出书籍

```bash
# 导出为 TXT（默认）
inkos export

# 导出为 Markdown
inkos export --format md

# 导出为 EPUB（手机/Kindle 阅读）
inkos export --format epub

# 只导出已通过审阅的章节
inkos export --approved-only

# 指定输出路径
inkos export --output ./my-novel.txt
```

## 8. 真人感与反 AI 系统

InkOS 内置三大后处理系统，让 AI 生成的文字更像真人写作。

### 8.1 系统概览

| 系统 | 作用 | 配置字段 | 默认 |
|------|------|---------|------|
| **反 AI 检测** | 降低 AI 痕迹（口语句式、突发性调整） | `enableAntiAI` | `true` |
| **真人感引擎** | 注入沉默层、自我矛盾、呼吸段 | `enableHumanity` | `true` |
| **情感注入** | 根据情感弧线增强情感表达 | `enableEmotion` | `true` |

### 8.2 配置方法

编辑 `books/<bookId>/book.json`，添加以下字段：

```json
{
  "enableAntiAI": true,
  "enableHumanity": true,
  "enableEmotion": true,
  "humanizerIntensity": 0.5,
  "humanitySamplesDir": "samples/my-style/",
  "maxErrorsPerChapter": 0,
  "maxReviewIterations": 3
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `enableAntiAI` | boolean | 启用去 AI 味后处理 |
| `enableHumanity` | boolean | 启用真人感引擎 |
| `enableEmotion` | boolean | 启用情感注入 |
| `humanizerIntensity` | number (0-1) | 去 AI 味强度（0.3 适中，0.8 强烈） |
| `humanitySamplesDir` | string | 真人写作样本目录（用于提取指纹） |
| `maxErrorsPerChapter` | number | 每章最大允许错误数（0 = 零容忍） |
| `maxReviewIterations` | number (1-5) | 最大审查修订轮数 |

### 8.3 使用真人写作样本

真人感引擎可以从你提供的真人写作样本中提取 12 维写作指纹：

1. 准备样本目录（如 `samples/my-style/`），放入 `.txt` 格式的真人写作样本
2. 在 `book.json` 中配置 `humanitySamplesDir`
3. 首次写作时系统自动提取指纹并保存到 `.inkos/humanity_profile.json`

**12 维写作指纹**：
- 句法维度：句长标准差、突发性指数、感叹号密度、问号密度、犹豫词密度
- 叙事维度：对话打断率、时间碎片占比、身体部位词密度、口语密度、视角偏移率
- 角色维度：自我矛盾率、不体面道具率

### 8.4 AI 痕迹检测

```bash
# 检测第 10 章的 AI 痕迹
inkos detect 10

# 检测所有章节
inkos detect --all

# 本地模式（不调用外部 API）
inkos detect 10 --local

# 查看统计
inkos detect --stats

# 使用声音档案
inkos detect 10 --voice casual

# 检测并自动修复
inkos detect 10 --fix
```

**声音档案选项**：`casual`（随意）、`professional`（专业）、`warm`（温暖）、`blunt`（直白）、`literary`（文学）、`webnovel`（网文）

## 9. 用户偏好学习

### 9.1 工作原理

当你修改 AI 生成的章节内容时，系统会自动记录你的编辑行为，分析你的写作偏好，并在后续写作中应用这些偏好。

**学习维度**：
- 语言风格：正式度、文学性、幽默感、黑暗程度
- 句式偏好：平均句长、短句比例、段落长度
- 词汇偏好：常用词、避免词
- 情感表达：强度、直接度
- 叙事偏好：动作密度、对话密度

### 9.2 启用学习

在 `book.json` 中设置：

```json
{
  "enableLearning": true
}
```

### 9.3 学习数据存储

学习数据保存在 `books/<bookId>/.inkos/learning/`：

```
.inkos/learning/
├── edit_log.json       # 编辑日志
└── preferences.json    # 偏好画像
```

### 9.4 冷启动

当编辑次数不足 5 次时，系统使用题材默认偏好（冷启动）。积累 5 次以上编辑后，系统开始应用你的个人偏好。

## 11. 守护进程与批量写作

### 11.1 启动守护进程

守护进程会在后台自动写作：

```bash
# 启动
inkos up

# 静默模式
inkos up -q

# 停止
inkos down
```

### 11.2 守护进程配置

在 `inkos.json` 中配置：

```json
{
  "daemon": {
    "schedule": {
      "radarCron": "0 */6 * * *",
      "writeCron": "*/15 * * * *"
    },
    "maxConcurrentBooks": 3,
    "chaptersPerCycle": 1,
    "retryDelayMs": 30000,
    "cooldownAfterChapterMs": 10000,
    "maxChaptersPerDay": 50,
    "qualityGates": {
      "maxAuditRetries": 2,
      "pauseAfterConsecutiveFailures": 3
    }
  }
}
```

**字段说明**：

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `schedule.radarCron` | `0 */6 * * *` | 雷达扫描频率（每 6 小时） |
| `schedule.writeCron` | `*/15 * * * *` | 写作频率（每 15 分钟） |
| `maxConcurrentBooks` | 3 | 最大并发书数 |
| `chaptersPerCycle` | 1 | 每周期章数 |
| `maxChaptersPerDay` | 50 | 每日最大章数 |
| `qualityGates.pauseAfterConsecutiveFailures` | 3 | 连续失败 3 次暂停 |

## 17. 常见问题排查

### 17.1 诊断工具

```bash
# 全面诊断
inkos doctor

# 修复 Node 运行时问题
inkos doctor --repair-node-runtime
```

### 17.2 常见问题

**Q: 提示 "API 认证失败"**

检查 API Key 配置：
```bash
inkos config show
inkos config show-global
```

确认 API Key 未过期，且 baseUrl 正确。

**Q: 写作时提示 "Book is locked by another process"**

说明有另一个进程正在写同一本书。等待完成，或手动删除锁文件：
```
books/<bookId>/.write.lock
```

**Q: 章节状态为 "state-degraded"**

说明写作过程中状态保存异常。修复：
```bash
inkos write repair-state <chapter-number>
```

**Q: 字数不达标**

系统会自动进行字数归一化（最多 1 次）。如果仍不达标，可以：
```bash
inkos revise <n> --mode rewrite --brief "扩充到 3000 字"
```

**Q: 如何查看伏笔状态**

```bash
# 查看所有伏笔
inkos hooks list

# 伏笔压力分析
inkos hooks pressure

# 手动标记伏笔回收
inkos hooks resolve <hookId>
```

**Q: 如何查看角色信息**

```bash
# 列出所有角色
inkos characters list

# 查看角色档案
inkos characters inspect "林轩"

# 角色数据完整性检查
inkos characters health
```

**Q: 如何更新到最新版本**

```bash
inkos update
```

### 17.3 日志查看

守护进程日志位于项目根目录 `inkos.log`。Studio 中可在 LogViewer 页面查看。

## 附录：完整工作流示例

### A. 从零开始写一本玄幻长篇

```bash
# 1. 安装
npm i -g @actalk/inkos

# 2. 初始化项目
inkos init my-novel
cd my-novel

# 3. 配置 LLM
inkos config set-global \
  --provider openai \
  --api-key sk-your-key \
  --model deepseek-chat \
  --base-url https://api.deepseek.com/v1

# 4. 验证配置
inkos doctor

# 5. 创建新书
inkos book create --title "吞天魔帝" --genre xuanhuan --platform tomato

# 6. 写前 5 章
inkos write next --count 5

# 7. 查看状态
inkos status

# 8. 审阅
inkos review list
inkos review approve-all

# 9. 继续写作
inkos write next --count 10

# 10. 导出
inkos export --format epub --output ./吞天魔帝.epub
```

### B. 启用真人感系统写作

```bash
# 1. 准备真人写作样本
mkdir -p samples/my-style/
# 将真人写的 .txt 文件放入该目录

# 2. 编辑 book.json 启用系统
# 在 books/<bookId>/book.json 中添加：
# {
#   "enableAntiAI": true,
#   "enableHumanity": true,
#   "enableEmotion": true,
#   "humanizerIntensity": 0.5,
#   "humanitySamplesDir": "samples/my-style/"
# }

# 3. 写作（系统自动提取指纹并应用）
inkos write next

# 4. 检测 AI 痕迹
inkos detect 1 --local
```

```bash

# 2. 启动守护进程

# 3. 查看日志
# 日志写入 inkos.log
```
