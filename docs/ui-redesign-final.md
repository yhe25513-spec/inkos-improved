# InkOS Studio UI 最终方案

> 基于 GPT 设计稿 + 你的实际代码 + 我的分析，融合后的最终方案。

---

## 核心原则

1. **Agent 是第一公民** — 用户不是在"写小说"，是在"指挥 AI 团队写小说"
2. **少即是多** — 每个视图只展示当前需要的信息
3. **渐进披露** — 常用操作默认显示，低频操作折叠
4. **不动业务逻辑** — 只改视觉和信息架构

---

## 一、左栏：从"功能罗列"到"工作流导航"

### 当前问题

左栏同时展示 8 个创作入口 + 书籍列表 + 会话列表 + 系统设置。用户 90% 的时间只在一个工作流里。

### 方案

```
┌────────────────────┐
│  InkOS STUDIO      │
│                    │
│  [ + 开始创作 ]    │  ← 大按钮，点击弹出创作模式选择
│                    │
│  ───               │
│  ⌂ 工作台          │  ← 图标 + 文字
│  📖 我的作品       │  ← 图标 + 文字
│  💬 会话           │  ← 图标 + 文字
│                    │
│  ───               │
│  ⚙ 设置            │  ← 图标 + 文字
└────────────────────┘
```

**关键变化**：
- 去掉所有 8 个创作按钮，改为一个"开始创作"按钮
- 点击后弹出模态框，让用户选择创作模式（长篇/短篇/同人/开放世界等）
- 书籍列表移到"我的作品"面板内，可折叠
- 会话列表移到"会话"面板内，可折叠
- 系统设置移到右上角

**为什么这样改**：
- 用户创建新作品是低频操作（几天一次），不应该在左栏占这么大空间
- 用户日常操作是"工作台 → 写下一章 → 审核"，左栏只需要导航到这 3 个地方
- 左栏宽度从 260px 缩到 200px（或保持 260px 但内容更稀疏）

### 关键变化

#### 2.1 当前任务区

- 显示当前章节标题 + 状态标签（执行中/已完成/等待审核）
- 可编辑（点击铅笔图标修改任务描述）
- 背景色随状态变化（执行中=淡红，已完成=淡绿）

#### 2.2 Agent 执行过程

- **这是 GPT 设计稿里最好的部分，必须保留**
- 横向流程图，每个 Agent 是一个节点
- 节点状态：✓ 已完成（绿色）、→ 运行中（橙色旋转）、○ 等待中（灰色）
- 点击节点可展开查看详情（当前代码已有的 PipelineStage 信息）
- 只在有 Agent 在执行时显示

**实现来源**：你的 [ToolExecutionSteps.tsx](packages/studio/src/components/chat/ToolExecutionSteps.tsx) 已经有 `PipelineStage[]` 数据结构，只需要从聊天消息中提取出来放到独立面板。

#### 2.3 生成结果区

- 三个 Tab：生成结果 / 章节大纲 / Agent 日志
- 正文用 serif 字体渲染（你的 [ChapterReader.tsx](packages/studio/src/pages/ChapterReader.tsx) 已经做得很好）
- 底部保留输入框，支持对生成结果进行修改指令
- 快捷指令行（指令模板/续写/改写/扩写/润色/总结）

#### 2.4 快捷操作

- 只保留 3 个主操作 + "更多"折叠
- 主操作：写正文（主色 oxblood）、修订优化（主色）、内容审核（主色）
- 更多工具展开后：角色管理、伏笔管理、剧情设定、世界观、存档管理、体验模式

#### 2.5 右栏（可折叠）

- 分为 4 个可折叠面板：章节进度、章节列表、主要角色、核心文件
- 默认：章节进度（展开）、章节列表（展开）、主要角色（折叠）、核心文件（折叠）
- 角色列表只显示名字 + 标签，点击展开看简介
- 右上角有"收起右栏"按钮，最大化内容区

## 五、与 GPT 设计稿的关键区别

| 方面 | GPT 设计稿 | 本方案 |
|------|-----------|--------|
| 左栏创作入口 | 6 个全部展开 | 1 个按钮 + 弹窗选择 |
| 顶部导航 | 页面级 Tab（工作台/数据分析/质量评估） | 面包屑 + 全局操作 |
| Agent 执行过程 | 横条流程图 ✅ | 横条流程图 ✅ + 点击展开详情 |
| 快捷操作 | 4 个主操作 + 6 个次要 | 3 个主操作 + "更多"折叠 |
| 右栏角色列表 | 全部展开，显示头像+简介 | 默认折叠，只显示名字+标签 |
| 生成结果输入 | 底部输入框 ✅ | 底部输入框 ✅ + 快捷指令行 |
| 仪表盘创作入口 | 4 个卡片 ✅ | 4 个卡片 ✅ |

## 六、总结

GPT 设计稿最大的贡献是提出了 **"Agent 执行过程面板"** 这个概念。这确实是你的产品与所有其他 AI 写作工具最大的差异化。

但它的问题在于：
1. 左栏没有真正精简（仍然展开了 6 个创作模式）
2. 顶部导航冗余（页面级 Tab 不应出现在全局导航）
3. 右栏信息密度过高（角色列表全展开）

本方案保留了 GPT 的好想法，修正了这些问题，并基于你的实际代码给出了可实现的路径。
